# Keep the sword thumb in control when it stops moving

The previous camera test surrendered automatic framing on look deltas or while a canvas look pointer was held. The sword button has its own pointer capture. Once a thumb crosses its 8 CSS px drag threshold, the native button enters steering and stays there even when the thumb pauses. Looking only at deltas incorrectly dropped manual ownership during that pause. The probe now also observes the existing captured HUD steering state; a simple tap still does not claim the camera.

Four native Chromium touch replays in the portrait Rook–Jack fixture exercise a sword tap, button drag and release, the same drag and pointer cancel, and a canvas drag. The drag starts as a button press during the actual counter opportunity, crosses the threshold diagonally, pauses, then reverses. A second contact is held on the movement stick in neutral during the drag. The two sword-drag cases each retain manual ownership for all 16 stationary frames (267 ms at the fixed 60 Hz test clock). During those frames the old input gate saw neither a look delta nor a canvas pointer. Both release and cancel cleared ownership. For this test, the drag can intentionally crop Jack: player input takes priority over automatic fit.

Run the pinned loopback reference build, then `native-probe.mjs FABLE_CHECKOUT DEPENDENCY_PROJECT live-framing` with each of `hud-drag`, `hud-tap`, `hud-cancel` and `canvas-drag`. Pass their four output directories in that order to `touch-counter-proof.py`. This uses Chromium's touch dispatch and the actual game's pointer handlers, unlike a direct injection of look deltas, but it is not physical iPhone validation. Holding the left thumb at neutral tests the two-contact routing, not moving-and-fighting ergonomics. No Fable source, assets, footage or playable build was changed or published.
