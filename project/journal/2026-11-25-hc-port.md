# herdr TUI tooling to herdr-core (hc)

Ask A12. We run under herdr-core (`hc`, `$HC_TERMINAL_ID`) and the Herdr app, not the old herdr multiplexer, so
everything gated on `HERDR_ENV=1` was dark: no peers in the session brief or the commit/push hooks, and the
question guard watched `herdr agent prompt` while agents now type with `hc send`.

- `.agents/hooks/peers.sh` replaces herdr-peers.sh. `hc ls` gives a terminal's launch folder, not where its agent
  works (this session: launched in meta, working here), so it reads `foreground.cwd` from `hc get` for each live
  non-shell terminal. Self is `$HC_TERMINAL_ID` (hc has no session ids). Goal: an hc `goal` label, else the
  status message the agent reports (`status.msg`; `hc get` gives status as {app, msg, state}).
- `guard-hc-send.sh` replaces guard-herdr-prompt.sh, keeping its shell parser. hc already refuses `send` to a
  blocked terminal (exit 9), so the guard refuses only what hc lets through: `send --force`, and `keys` /
  `interrupt` (they answer or dismiss a dialog) unless `hc get` says live and not blocked. herdr-prompt.sh and
  herdr-question-open.sh are gone: hc's own refusal is the wrapper now.
- Owner records (`scratch-dir`), commit timings (`commit.sh`) and land (`land.mjs`) record `$HC_TERMINAL_ID`;
  `lane-live` counts a scratch folder live while hc says its owner's terminal is; worktree.mjs labels the hc
  terminal instead of renaming a pane.
- Tests use a fake `hc` (bash + jq) on PATH and scrub `HC_*` from sandboxes, so the suite never touches the real
  core. Skills, AGENTS.md, dev.md and the asks README name hc.
- Not here: `~/.claude/set-label.sh` (dotfiles) still writes the old herdr panel token; making it `hc label
  $HC_TERMINAL_ID goal=...` would feed peers.sh's goal column. All of this is repo-kit's code: phase 2.
